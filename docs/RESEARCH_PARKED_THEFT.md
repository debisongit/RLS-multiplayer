# Research: steal ANY parked car, every model parked, same config on steal

Claude A. Untested in-game. Owner (exact): "EVERYONE must be able to steal ALL parked cars that spawn in, not only the ones that spawn from your own traffic pool", "the parked cars that spawn in must be able to spawn EVERY car that is available (it doesn't matter if it doesn't have a simplified version)", "once you steal it, it must make sure it is the same config. Last time we stole a Pessima that was the TUNED config but the normal slow one spawned in instead." This undoes the 0.4.60 "own car only" rule for PARKED cars (see `docs/RESEARCH_PASSENGERS.md` section 4, now out of date).

## 1. Verified in the RLS source (read only)
- Parked cars are spawned by `parking.lua setupVehicles` (`overhaul/integration/services/parking.lua:1208`): `params.filters.Type = {propparked = 1}`, `params.allConfigs = true`, `core_multiSpawn.createGroup(amount, params)`, then `core_multiSpawn.spawnGroup(group, amount, {name = "autoParking", customTransforms = ..., randomPaints = true})`. So the paint is random after the pick: nothing in the group entry holds it.
- `parking.lua onVehicleGroupSpawned(vehList, groupId, groupName)` (line 1340) is called with the spawned ids and group name `"autoParking"`; `onVehicleDestroyed(vehId)` (line 1358) removes the car from `parkedVehIds`, frees its spot and drops its data. So a plain `o:delete()` is enough for RLS's bookkeeping (we still never call `parking.removeVehicle`, as `RESEARCH_PLATES_THEFT.md` says). RLS tops the parked cars up to its cap later (`syncParkedCount`), so a stolen car's place can get a new parked car: acceptable, logged.
- `trafficConfigFilter.isConfigEligible(model, config, params)` (`overhaul/integration/patches/trafficConfigFilter.lua`) with a parked intent (`isParkedSpawnIntent`: Type filter holds only `propparked`) uses the `|parked` rules: no power rule, no wheel/engine-slot rule, but it still rejects `Frame`/`joesJunkshell` Config Types, `police` names and part values like `wheel_square`. It does NOT reject taxis (we do: `lib/trafficVariety dropBlocked`, words `police`, `taxi`).
- RLS never maps a stand-in to ONE real config. The only stand-in code is `trafficVehicle.lua:139` (model name from the config file name). The stand-in config names (`legran_sedan_pre_s_parked`) carry the model and a body/trim variant, not a part config. So an exact config cannot be read back from a stand-in.

## 2. Why the Pessima came out slow (the cause I can show)
The parked car was a `simple_traffic` stand-in; `carInfo` guessed a real config from its name (`T.realModel` + `stolenValue.resolve`, "typical" or the closest name match). A stand-in cannot say "tuned", so the base config came out. A FULL parked car would not have had this problem (its `partConfig` is its own `.pc` path).

## 3. What was built
### 3.1 Same config on steal (`rlsmp/lib/theft.lua exactOf`, `rlsmp/theft.lua carInfo`)
`carInfo` order, logged as `theft config: ... (how)`:
1. `full`: the object is not a stand-in: its own `partConfig`. A `.pc` path is passed to the spawn as is; an inline part config (string starting with `{` or a table) is kept whole as JSON text (`cfgJson`, up to 8000 chars) and decoded for the spawn. UNVERIFIED: that `partConfig` of a parked car is a path (the old code relied on it) and that `spawnNewVehicle` accepts a decoded table as `config`; the log line prints the first 80 characters of `partConfig` so the next log shows it.
2. `map`: a stand-in that our own group pick made. Our `createGroup` wrapper picks FULL entries; a share (`parked.simplifiedShare`) is then shown as a stand-in of the same model and body style, and `{stand-in name -> real model/config}` is remembered (`lib/theft noteIntended`). `rlsmp_trafficVariety.onVehicleGroupSpawned` (RLS's `parking.lua` gets the same hook with group name `autoParking`) binds each spawned stand-in to its pick by the stand-in's config name, not by order (two stand-ins with the same name look the same, so which gets which does not matter). If the hook did not run, `carInfo` binds lazily the same way. Picks expire after 15 minutes.
3. `standin-guess`: a stand-in nobody remembered a pick for (the game's own spawn without our wrapper, or the wrapper failed). The old guess, logged as a warning with `a stand-in nobody remembered a pick for`. This should now be rare; with `parked.fullPool` on and the pool ready every wrapper-made parked car is `full` or `map`.
- The stand-in a pick is shown as is a GUESS for the body style: `lib/simplified pickSimpleFor` needs a shared word of 3+ letters between the stand-in name and the real config key (`sedan`, `wagon`); with none the car stays a full car. If a stand-in looks different from what you get, set `trafficVariety.parked.simplifiedShare` to 0 (always full cars).
- Tuning: a `.pc` path holds the whole part list and vars, so a tuned `.pc` stays tuned. UNVERIFIED: any tuning applied to a live parked car after it spawned (parked cars are not tuned by RLS) would not be in the snapshot; we do not read the live part tree.
- Limits: the server keeps only a `.pc` path (`rememberCar`, 160 chars) for the restore after a rejoin; an inline part config is used for the spawn but not kept for recall.

### 3.2 Parked pool (`rlsmp/trafficVariety.lua`, config `trafficVariety.parked.fullPool`, `simplifiedShare`)
- `fullPool` (default true): for a parked group the game's own offer (only stand-ins, `Type = propparked`) is replaced by a parked pool built from EVERY spawnable model of the game's traffic Types (`getBaseGroupParams`): up to `2 x pool.configsPerModel` (10, at most 20) random configs per model that pass `isConfigEligible(model, config, {filters = {Type = {propparked = 1}}})` (RLS's parked rules), minus `excludeWords` junk (also the `drivable == false` flag), minus police and taxi words. Random each session, so over sessions every config is reachable. Rarity weights, `maxShare` and the round robin (own memory `memParked`) apply as for traffic. Built to the end at the first parked group if not ready (one-time cost); if still empty the game's offer is used (logged).
- `simplifiedShare` (default 0.5, 0 = always full cars): see 3.1. Needs no `simplified.enabled`.
- `fullPool` false: the game's own parked offer as before (stand-ins untraceable, so steals fall to the guess).
- The old `simplified.lua` upgrade of stand-ins at stealable spots still works when enabled; it picks a random config of the model (`fullEntryFor`) and does not use the remembered pick yet.

### 3.3 Stealing a parked car of another game
Design in `docs/PROTOCOL.md` ("Parked cars of every game"). Short version:
1. Every game sends `rlsmpParkedReport` (BeamMP id `pid-vid`, real model, exact config, plate, position) about every 30 s and when its list changes. The server keeps the table (max 40 per player, one report per 3 s, 100 s lifetime).
2. The server tells each player the other games' parked cars within 120 m (`rlsmpParkedNear`). The client matches them to the remote vehicles BeamMP shows (by id, object within 10 m of the reported spot) and uses the REPORTED position for the stealable pick, so both sides agree even when the synced copy jitters over a 4 m cell border.
3. Check/Start/Inspect/Hint name the car by `sid`. The server accepts own-game cars as before, and remote cars only from its table: owner online, report fresh, the thief's fresh server position within `theft.radius` + 10 m, `stealableAt(reported position)`, tools, cooldown, and ONE steal per car (claim).
4. At the end of the timer (failure roll first) the server asks the OWNER's game (`rlsmpParkedTake`). The owner's game re-checks the car, takes the snapshot, deletes the car and answers (`rlsmpParkedTaken`). Only then the server uses up the tools and sends the snapshot to the thief inside `rlsmpTheftResult`. The thief's game waits until BeamMP has removed the remote car (at most 6 s), then spawns the real car with `spawnStolen` (the same spawn options as the local convert) and sends `rlsmpTheftDone`. The server records the OWNER's snapshot (plate, model, config, paints), never the thief's claims.
5. Owner offline or slow: 12 s timeout (also when the owner leaves), the thief gets a message, tools are not used, the claim is released. A late answer is ignored: the owner's game already deleted the car, so that parked car is lost (logged). The owner's RLS may top the parked cars up and spawn a new one; that is acceptable.
6. A remote steal is one more car for the thief (a local convert is net zero): the client refuses when `mp.ownCount()` is at the server's `maxCars`.
- Still never stolen: AI traffic, police, taxis, other players' real cars, a car another player already stole and drives (not in the table: the reporting game skips converted cars), a car taken by someone else (claim and `gone` list).
- Local steals work as before (no round trip). `simplified.lua` and `liveByPlate` stay own-game only; `vehicleGuard` is unchanged (the thief enters the car he spawned himself).
- Scout tips (`market.lua`) now accept listed remote cars and use their REPORTED position. Fixed on the way: the client's scout list had no `sid` since 0.4.60, so every scout tip was refused; it carries `sid` now.

## 4. Verified vs guessed (summary)
- Verified (source): the parked spawn params, `onVehicleGroupSpawned` args and group name, `onVehicleDestroyed` cleanup, the parked filter rules, no stand-in to config mapping in RLS.
- Verified (tests with fakes): the report, near list, claim, take/hand-over, timeout, wrong token/player, far snapshot, owner left, duplicate steal, record from the snapshot, tuned config through the whole chain, client matching by BeamMP id, no remote delete, pool without stand-ins, no police/taxi/junk.
- Guessed / unverified in the game: that BeamMP syncs far, inactive pooled parked cars (a remote car is only offered when its object exists here, so far ones are skipped); `partConfig` of a parked car being a path; `spawnNewVehicle` with a table `config`; `MP.GetPlayerVehicles` keys; the order BeamMP removes the remote car vs our spawn (we wait up to 6 s); stand-in body-style matching by word; that `core_vehicles.getModel("simple_traffic")` lists the parked stand-ins; the cost of building the parked pool at the first group.
