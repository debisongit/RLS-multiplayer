# Research: why only about 5 traffic cars exist, and how the count reaches the minimum

Claude A. Sources: RLS source (read only) `career/police/playerDriving.lua`, `integration/services/police.lua`, `events/utils.lua`; the owner's log (build 0.4.45). Vanilla `gameplay_traffic` (`setupTrafficHelper`, `setActiveAmount`, the vehicle pool) is NOT available here, so what it does inside is inferred from the log. Nothing here was played.

## What the log and the RLS source show
- Career start (`playerDriving.setupTraffic`): `trafficAmount = settings trafficAmount` (minus 1 when the player has no vehicle yet, at least 0), then `gameplay_traffic.setupTrafficHelper(trafficAmount, {simpleVehs, autoLoadFromFile, police}, parkingAmount)` followed by `gameplay_traffic.setActiveAmount(trafficAmount)`. `setupTrafficHelper` builds the group ONCE (asynchronously: it calls `core_multiSpawn.createGroup(amount, params)`, then `spawnGroup`, name `autoTraffic`) and the police and taxi "special vehicle providers" take cars from it.
- Log: `variety traffic group: want=4 ... picked=4` (205.4 s), `Special vehicle provider "police": requested 1, allocated 1`, `Vehicle group spawning in progress (n / 5)`, `Traffic system started with 5 active / 5 total vehicles` (220.6 s), then `distance: ... activeAmount=4 cars=5` all session. So 5 = 4 group cars + 1 police car; the pool ("total") is 5.
- `setActiveAmount(n)` (RLS calls it in `setupTraffic`, `onSettingsChanged` (`playerDriving.lua:300`), events `events/utils.lua:58,87`, car meets, travel journal) only says how many cars of the existing pool are ACTIVE. RLS also resets it to the player's own setting on every `onSettingsChanged`, which our parked-cars top-up triggers (so `holdMin` exists). No RLS code ever grows the pool afterwards; the only way RLS adds a car to traffic is `gameplay_traffic.insertTraffic(id, ignoreAi, noPooling)` (police, jobs, garage spawn).
- Our quota (`min=10`) arrived at 210.5 s and the group was already built at 205 s with the defaults (the variety settings arrive in the same second as the quota, after the group). `raiseToMin` therefore changed a number, not the cars.

## What was built
1. Group size (a): `rlsmpTrafficVariety` now also carries `minAmount` (and `maxCars`, BeamMP's per-player limit via `MP.Get(MP.Settings.MaxCars)` in a pcall, 0 = unknown). The createGroup wrapper asks for `min(quota, minAmount)` cars when the group is not tiny (>= 2), is not police or parked, and no traffic car exists yet (`lib/trafficFill.groupSize`). This only helps when the settings are here before the setup group; in the log they were not, hence (b).
2. Fill (b): `rlsmp/trafficFill.lua`, checked every second. `want = rlsmp_traffic.getWant()` = min(quota, minAmount). `have` = cars in `gameplay_traffic.getTrafficData()` except the player's, other players' and garage cars (police counts). When `have < want`, at most one car every 4 s: model from `trafficVariety.pickReplacement` (excludeWords, rarity, area weights, round robin, brand census; else something the game offered lately), place from `gameplay_traffic_trafficUtils.findSafeSpawnPoint/finalizeSpawnPoint` 150 to 400 m behind the camera (the same calls as RLS's taxi call, `taxi/core.lua:854`), then `rlsmp_trafficSwap.spawnNew`: `core_multiSpawn.spawnGroup({{model, config}}, 1, {name = "rlsmpFill", customTransforms})`, `onVehicleGroupSpawned` -> `insertTraffic`. Same frame guard and `canBuild` as the re-roll (no chase, no pause, no slow frames), same 25 s timeout and shared failure switch (3 failures, then it stops).
3. Gates: traffic state `on`; `activeAmount >= want` (an event or job cut the amount, or it is not raised yet: wait); not in a chase; BeamMP: own cars (`MPVehicleGE` `isLocal`) below `maxCars - 3` (unknown: below 60), else refused with a warning.
4. Never above `want`: spawning stops when `have + 1 >= want` counting the car on its way; nothing is ever deleted by this. Cars it added are left alone by unjam, the re-roll and the swap for 120 s (`rlsmp_trafficFill.isNew`).
5. Log: `fill: have=H want=W, adding ...`, `fill: spawning ...`, `fill: car ID model/config added (...) have= want= spawned= refused=`, `fill: waiting (reason)`, `fill: refused (reason)` (maxCars, no place, no pick, failures), `fill: done ...`, `fill: the game asked for a traffic group of N, the server wants M: group size raised`.

## Guessed / to check in the next log
- That vanilla keeps an inserted car in place (a fresh traffic car starts with `respawn.activeRadius = distance + 500`, so it should not be recycled at once) and counts it for `activeAmount`.
- That `findSafeSpawnPoint` returns a spot out of sight; if the log says `refused (no place)` the camera API or the arguments differ.
- That the `MaxCars` call works on the server (the log line `maxCars=` shows what arrived).
- The police unit comes from the same group: a raised group of 10 gives 10 cars plus possibly the police car, so `have` can end at want + 1 (nothing is removed).
